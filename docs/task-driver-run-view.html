Task / Driver / Run 协议视图

这是对 docs/task-driver-run-spec.md 的“可视化阅读版”，用于快速对齐：哪些是长期对象、哪些是一次执行、push/pull 分别推/拉的是什么，以及 NanoGhost 如何只做 Gateway/Executor/Surface。

View 1

全局协作链路（控制面 / 执行面）

Task System 负责控制面：DriverPump tick / Driver evaluation / Task state transition / Run creation / Feedback routing。 NanoGhost 负责执行面的一部分：执行 Run（作为 Executor）以及把反馈呈现给人（作为 Surface）。

控制面：Task System 投递层：Delivery / Inbox 执行/交互：NanoGhost
View 2

Run 分派 vs Feedback 投递

你在 spec 里强调的关键拆分：定时只影响 DriverPump tick；push/pull 是传输；Run 和 Feedback 是两条流。

定时任务的“定时”只决定什么时候 tick；tick 命中后才会产生 Run 和/或 Feedback。

Delivery 层：push / pull / subscription 怎么落地

轮询如果存在，应发生在 gateway/worker，而不是发生在 LLM 的推理循环。

轮询发生在 Gateway/Worker 禁止：LLM 自己轮询
Example 1

例子：定时任务（每天 9:00 汇总 -> 发回 NanoGhost）

这个例子回答：定时 pull 到底 pull 什么？——定时的是 DriverPump tick；pull 的是 inbox 或 claim run（发生在 gateway/worker 层）。

  1. 用户在 NanoGhost 里发起：创建一个每天 9:00 的汇总任务（CreateTask）。
  2. Task System 存储 Task，绑定 driver（例如 “news.digest.v1”）和调度策略（cron）。
  3. 每天 9:00，DriverPump tick 触发 driver evaluation：决定要执行一次汇总 Run。
  4. Task System 创建 Run（RunQueue/RunStore），选择 executor_ref（例如 agent.nanoghost.research）。
  5. Run 分派可选：push DispatchRun 到 NanoGhost；或由 NanoGhost worker claim run。
  6. NanoGhost 执行一次 Agent run，回传 ReportRunResult。
  7. Task System writeback：更新 Task 状态/游标/产出 artifacts。
  8. Task System 生成 FeedbackMessage（例如 important_not_urgent），写入 FeedbackInbox 并按策略投递。
  9. NanoGhost gateway 将反馈插入会话（after_current_turn）或写入 inbox；下一轮 agent 读到。
Example 2

例子：事件驱动（CI 失败 -> 立刻打断会话）

事件可以来自外部 webhook；Task System 只在“状态变化”时产出反馈，并使用 immediate_insert 投递策略。

  1. 外部系统（CI/GitHub）把失败事件推到 Task System 的入口。
  2. driver evaluation 命中：Task 从 running -> failed（state transition）。
  3. Task System 生成 FeedbackMessage：priority=important_urgent，delivery_policy=immediate_insert。
  4. Delivery 使用 push（webhook/queue/stream）把反馈送到 NanoGhost gateway（幂等 + 重试）。
  5. NanoGhost 立即在当前会话插入一条系统消息，agent 得到中断式通知并进行响应。
Checklist

你可以用这 6 个问题检查设计是否清晰

  • 这个信息是 Run 分派，还是 Feedback 投递？
  • 它应该 push 还是 pull？轮询发生在谁？（必须不是 LLM）
  • 触发点是 state transition / run lifecycle 吗？还是噪音指标？
  • delivery_policy 是 immediate_insert / after_current_turn / throttle / digest 哪个？
  • 是否需要 inbox 以实现可审计、可重试、可去重？
  • 是否需要把“投递到 NanoGhost”与“进入上下文”严格分离？
