2特性 已实装能力
◉单入口收口
Router.submit(RouteEnvelope) 是唯一消息入口；入站/出站共用同一信封，靠 direction 分流。旧 InboundDispatcher / OutboundEnvelope 已移除。
▤统一内容形态
内容一律 blocks（有序）：text / markdown / image / file。两份机制（机制 vs 工具）填的东西完全一样。
☰常驻收件箱
InboxHub + ResidentConsumer：每端点 FIFO；端点内串行、端点间并发；按 kind 分派。忙闲只影响「何时被喂」。
⏱事件源可插
Timer(scheduler) · SubAgentPool · Watcher(变化才报) · 手动 —— 产出同一种事件，走同一条队列。
⧉子 Agent 池
后台 / 并行（默认上限 3）/ FIFO 排队 / 完成回报父端点。一任务 : N 子 Agent。
⇄通道可插拔
Channel / Registry / Directory / Manager：飞书是其一；端点为动态注册（收到消息即登记）。
⛨出站护栏
ACL(按 agent) · 限速(20/60s/端点) · 审计(Auditor) · 防环(hop≤4) · 出站镜像。统一挂在这一个出口上。
↓优雅降级
markdown 不支持 → text；文件通道不支持 → 文本行（路径/名），信息不丢。
⏲自助定时任务
schedule_task / list / cancel：cron / interval / at；agent（含子 agent）自建，最长 5s 生效、无需重启。
🧠记忆
写入流水线 memory/pipeline.py；长期记忆注入走索引（memory_inject=index），正文按需 memory_read。
▣MCP 接入
capture（闲鱼采集）+ ticketcore（事件单）两个 http_sse 端点；工具表可 reload。
➟结果出口 Sink
环形缓冲 + 可选 JSONL 落盘 + 订阅者；子 Agent 完成也落 Sink。渠道是订阅者。
3字段设计 RouteEnvelope（统一信封）+ blocks
RouteEnvelope channel/route.py · 入/出站共用
directionstr*"inbound" / "outbound"（分流依据）
kindstr*channel_message / text / timer / subagent_done / event…
deliverystr"reply"（默认）/ "send"
source_addrstr来源地址 feishu:oc_xxx
target_addrstr目标地址（单）
toList[str]收件人 0..N；空 = 回来源
payloadAny任意原始内容（入站事件放这）
textstr文本正文（简单场景）
imagesList[str]base64 图（data URL）
blocksList[Dict]有序消息块（推荐）
reply_tostr?要回复的消息 id
reactionDict?表情反应
agent_keystr授权 / 命名空间（默认 "default"）
summarystr摘要（审计 / 日志）
route_keystr路由键
metaDict元数据
blocks 有序内容 · 唯一形态
{"type":"text", "text":"…"}plain
  纯文本 · 不渲染（msg_type=text）
{"type":"markdown", "text":"…"}render

  本机文件 ≤10 · 任意目录
